# Plex Media Server internals and how its architecture differs from Jellyfin (as of October 2026)

Reference notes for someone considering building a media server from scratch. Research date: 2026-10-13. Sources are mostly Plex support articles, Plex forum threads (including staff posts where identified), python-plexapi source, Tautulli source, and the Servarr wiki. Plex is closed source, so much of the "internals" material is community reverse-engineering; where a claim is only forum-sourced that is noted.

---

## Key Question 0 (context): What are the core moving parts of Plex Media Server (process, database, scanners/agents, transcoder, streaming, API, playback reporting, remote access)?

### Takeaway
PMS is a single closed-source native server process that owns a SQLite library database (`com.plexapp.plugins.library.db`), drives a built-in scanner + "new agent" metadata pipeline (with an end-of-life embedded Python 2.7 framework kept alive for legacy agents/scanners), shells out to a private FFmpeg fork ("Plex Transcoder", being rebuilt on FFmpeg 6.1 in 2025) plus a separate `EasyAudioEncoder` helper, and exposes an XML/JSON HTTP API on port 32400 authenticated by `X-Plex-Token`. Everything identity-related (accounts, device registry, sharing, remote access, watchlist) lives on plex.tv.

### Cited Findings

**Process, database file and schema**
- The library database is `com.plexapp.plugins.library.db` in the `Plug-in Support/Databases` folder and can be opened with the `sqlite3` tool; community queries join `metadata_items` -> `media_items` (on metadata item id) -> `media_parts` (on media item id); `media_items` has a `bitrate` column used to find items lacking analysis; `media_parts` holds file paths and has an `extra_data` column (users query it for `deepAnalysisVersion`); `media_streams` has a `url` column; `metadata_items` has `guid` and `metadata_type` columns — [Plex forums: HOWTO query data from PLEX on a Mac](https://forums.plex.tv/t/howto-query-data-from-plex-on-a-mac/11636.md); [Plex forums: Plex DB where is the flag for --analyze-deeply](https://forums.plex.tv/t/plex-db-where-is-the-flag-for-analyze-deeply/176628.md)
- Path/GUID storage formats: `section_locations.root_path` holds a library's root path; `metadata_items.guid` and `media_streams.url` (subtitle file paths) use a `file:///` prefix and are URL-encoded (spaces as `%20`); `media_parts.file` uses plain paths without `file:///`. `metadata_items` has `BEFORE UPDATE` / `AFTER UPDATE` triggers (`fts4_metadata_titles_before_update_icu`, `fts4_metadata_titles_after_update_icu`) that maintain a full-text-search table `fts4_metadata_titles_icu` (`docid`, `title`, `title_sort`, `original_title`); the triggers must be dropped before bulk-editing and recreated afterwards — [Plex forums: HowTo Plex database modification - moving media](https://forums.plex.tv/t/howto-plex-database-modification-moving-media-the-right-wrong-way/126701)
- `metadata_item_settings` is the per-account watch-state table: columns include `account_id`, `view_offset`, `view_count`, `last_viewed_at` (shown via `pragma table_info`); marking an item watched inserts a row/increments `view_count`, marking unwatched sets it to 0; parents (season/show) get their own rows with the same guid — [Plex forums: sqlite3 access to "watched" status](https://forums.plex.tv/t/sqlite3-access-to-watched-status/81143.md)
- Plex's official support article for moving view state between installs works by `.dump metadata_item_settings` from `com.plexapp.plugins.library.db` with sqlite3 and importing into the other install — [support.plex.tv: Move viewstate/ratings from one install to another](https://support.plex.tv/articles/201154527-move-viewstate-ratings-from-one-install-to-another/)
- `metadata_items.guid` and `metadata_type` "encode item type and agent source" (forum-level summary, not an official schema) — [Plex forums: HOWTO query data from PLEX on a Mac](https://forums.plex.tv/t/howto-query-data-from-plex-on-a-mac/11636?page=3)
- Users report library slowness from an ever-growing database — [Plex forums: Slow library performance due to increasingly growing database](https://forums.plex.tv/t/slow-library-performance-due-to-increasingly-growing-database/740511/1)

**Scanners and agents (new vs legacy)**

- When the new "Plex Movie" agent shipped (2020), the original was renamed "Plex Movie (legacy)" — [Plex forums: New Plex Movie agent](https://forums.plex.tv/t/new-plex-movie-agent/616169.md)
- New agents are configured per library; the server-level Agents settings page applies only to legacy agents — [Plex forums: only Plex Movie](https://forums.plex.tv/t/only-plex-movie/757216)
- February 2026 forum reply: legacy agents are deprecated and will eventually be retired (announced years ago); recent PMS releases hide them but they can be re-enabled under library setup options — [Plex forums: Missing agents and scanner files](https://forums.plex.tv/t/missing-agents-and-scanner-files/936305.md)
- Plex Plugin Framework (v2) is a sandboxed Python 2.7 framework; plug-ins can act as metadata agents — [plex-plugin-docs overview](https://plex-plugin-docs.readthedocs.io/en/latest/overview.html)

Users report the bundled interpreter as Python 2.7.17 (and 2.7.12 via `PlexScriptHost.exe` on Windows); `Framework.bundle` lives in the PMS `Plug-ins` folder; scanners are plain Python scripts that do not use the framework (no framework logging, only `print`); the outdated bundled Python breaks HTTPS certificate verification for scanners/agents — [Plex forums: What happened to dev.plexapp.com](https://forums.plex.tv/t/what-happened-to-dev-plexapp-com/849957.md); [Plex forums: Plex python errors](https://forums.plex.tv/t/plex-python-errors/746656.md); [Plex forums: HTTPS broken](https://forums.plex.tv/t/https-broken/216635); [Plex forums: Scanner Limitations](https://forums.plex.tv/t/scanner-limitations/49440)
- HAMA (HTTP AniDB Metadata Agent) is a long-running community Python agent (thread at page 97+) pulling anime metadata from AniDB/TheTVDB; AMSA is a fork — [Plex forums: [Rel] HTTP Anidb Metadata Agent (HAMA)](https://forums.plex.tv/t/rel-http-anidb-metadata-agent-hama/40470?page=97); [github sirterrific/amsa](https://github.com/sirterrific/amsa)
- 2024 community advice: use the built-in Plex Series / Plex Movie agents; TheTVDB and TheMovieDB legacy agents are "outdated" — [lemm.ee thread](https://lemm.ee/comment/13793204)

**Transcoder**
- Plex's transcoder is "a heavily customized FFmpeg fork". In June 2025 Plex announced a "Transcoder Upgrade" preview: a fresh fork of FFmpeg 6.1 containing only the features PMS needs, intended to make future upgrades easier (weeks rather than months, per Plex's Chris Decker), with selective 7.x backports; pre-alpha builds were PMS 1.42.1.10069 (links updated 2025-08-13). Plex said Dolby Vision transcoding beyond direct play is unlikely until patents expire, and that it is building runtime-loadable codec libraries to manage licensing costs — [Plex forums: Transcoder Upgrade Forum Preview](https://forums.plex.tv/t/transcoder-upgrade-forum-preview/924241)
- Historically the LICENSE shipped with Plex Transcoder pointed at a 2016 ffmpeg source tarball on Plex's file server; a later thread asks where the current fork source is (unresolved) — [Plex forums: Plex new transcoder source code LGPL](https://forums.plex.tv/t/plex-new-transcoder-source-code-lgpl/179121)
- `EasyAudioEncoder` (EAE) is a separate helper binary shipped with PMS (not part of ffmpeg); the transcoder is invoked with codec options such as `-c:a eac3_eae -b:a 1280k` and hands audio to EAE; a 2026 report says TrueHD/MLP transcodes broke after PMS 1.43.3 because the transcoder writes `.mlp` files into the EAE handoff — [Plex forums: TrueHD/MLP audio transcodes fail](https://forums.plex.tv/t/truehd-mlp-audio-transcodes-fail-transcoder-writes-mlp-files-into-eae/940690); [Plex forums: Time for Hardware Transcoding?](https://forums.plex.tv/t/time-for-hardware-transcoding/158412?page=2)
- Hardware-accelerated streaming requires an active Plex Pass; PMS v1.21.0+ in general; Intel hardware tone mapping needs v1.29.2+ and Kaby Lake or newer (Tiger Lake or newer on Windows, 64-bit builds only); NVIDIA hardware tone mapping needs driver 470.141.03+; Unraid NVIDIA tone mapping needs Unraid 6.9.0 beta 35+ — [support.plex.tv: HDR to SDR tone mapping](https://support.plex.tv/articles/hdr-to-sdr-tone-mapping/) (via search summary); [Plex forums: Server/Transcoding/PlexPass](https://forums.plex.tv/t/server-transcoding-plexpass/816242.md)
- Subtitle burn-in is single-threaded; if video bitrate exceeds one CPU core's burn capacity you buffer even with HW transcoding — [Plex forums: Subtitles slowing down transcoding?](https://forums.plex.tv/t/subtitles-slowing-down-transcoding/800198.md)
- "Plex Universal Transcoder" as a *new 2025–2026 product* could not be confirmed: the only claim is an undated third-party page (Winxvideo) saying Plex "will replace" Plex Transcoder with a Universal Transcoder; no Plex source says this. The term "universal transcoder" historically refers to the `/video/:/transcode/universal/...` endpoint family — [Plex forums: param for universal transcoder](https://forums.plex.tv/t/param-fir-universal-transcoder/32346); [winxdvd.com page](https://www.winxdvd.com/video-transcoder/plex-transcoding.htm)

**Streaming decisions / protocols**
- Web-client requests to the universal transcode endpoint pass `directPlay`, `directStream`, `protocol`, `videoResolution`; the "universal transcoder" parameter is client-side because it selects between an old and a new endpoint — [Plex forums: param for universal transcoder](https://forums.plex.tv/t/param-fir-universal-transcoder/32346); [Plex forums: transcoding direct play video resolution bitrates](https://forums.plex.tv/t/transcoding-direct-play-video-resolution-bitrates-etc/189708.md)

- Client profile `TranscodeTargets/VideoProfile` support `protocol` values `http`, `slss`, or `hls` (DLNA-era doc; DASH not mentioned there) — [Plex forums: Writing profiles for DLNA devices](https://forums.plex.tv/t/writing-profiles-for-dlna-devices/38060)
- Plex ships hidden per-device XML profiles in `Resources/Profiles` (overwritten on update); user overrides go in `Profiles/` under the PMS data directory, same file name overrides — [Plex forums: Writing profiles for DLNA devices](https://forums.plex.tv/t/writing-profiles-for-dlna-devices/38060)

**Playback reporting: websocket, webhooks**
- Tautulli connects to `ws[s]://<PMS>/:/websockets/notifications` sending `X-Plex-Token` as an HTTP header; messages are JSON wrapped in `NotificationContainer` with a `type` field; `playing` -> `PlaySessionStateNotification[0]` -> `ActivityHandler(timeline=...)`; `timeline` -> `TimelineEntry[0]` -> `TimelineHandler`; `reachability` -> `ReachabilityNotification[0]`; reconnect loop with `WEBSOCKET_CONNECTION_ATTEMPTS`/`WEBSOCKET_CONNECTION_TIMEOUT`, ping/pong keepalive, and on sustained disconnect it calls `plextv.notify_token_expired()` — [Tautulli plexpy/web_socket.py](https://raw.githubusercontent.com/Tautulli/Tautulli/master/plexpy/web_socket.py)

- python-plexapi asks plex.tv `/api/v2/resources?includeHttps=1&includeRelay=1&includeIPv6=1` to discover server connections including relay — [python-plexapi myplex.py](https://raw.githubusercontent.com/pkkid/python-plexapi/master/plexapi/myplex.py)
- Tautulli's websocket URL example uses a `*.plex.direct` hostname (`ws://172-19-64-45.<hash>.plex.direct:32400/...`), i.e. plex.tv-issued DNS names that embed the server IP for TLS — [openHAB community thread](https://community.openhab.org/t/plex-binding-player-state-not-updating-no-updates-on-stop/15978)

### Inferences
- The schema shape (`metadata_items` 1-to-many `media_items` 1-to-many `media_parts` 1-to-many `media_streams`, plus `metadata_item_settings` keyed by `(account_id, guid)`) is effectively a normalized "logical item / physical version / file part / stream" model. Jellyfin's `BaseItem` + `MediaSource` + `MediaStream` model is the same shape, so a new server should adopt it; the main difference is that Plex keys watch state by `guid` (so re-matching/re-adding an item preserves state) rather than by item primary key.
- Plex's new agents (`tv.plex.agents.movie` / `tv.plex.agents.series`) are not plugins at all: metadata comes from Plex's own cloud metadata service and the server merely stores `plex://` GUIDs plus external `Guid` children (`tmdb://`, `tvdb://`, `imdb://`, exposed via `includeGuids=1`). This is why integrations only need `includeGuids=1` on `/library/sections/{id}/all` to map Plex items to TMDB/TVDB. (The cloud-service claim is an inference from the EOL of the local Python framework and the per-library-only configuration of new agents.)
- The "legacy Python 2.7 embedded framework" is a cautionary tale: once the server team stopped owning it, HTTPS broke, and 2026 forum posts still show users fighting to re-enable hidden legacy agents. A new server should keep metadata providers as *out-of-process* services behind a stable HTTP contract (or as sandboxed WASM/JS) rather than embed an interpreter in the server binary.
- The 2025 FFmpeg 6.1 re-fork plus "runtime-loadable codec libraries" means Plex pays per-codec licensing and will keep the transcoder closed; EAE being a separate licensed binary is the same pattern for AC-3/E-AC-3/AAC encoding. A from-scratch server built on stock FFmpeg + libass avoids this but inherits patent exposure for AAC/AC-3 encoders in commercial distribution.
- `metadata_type` integer codes (community convention: 1 movie, 2 show, 3 season, 4 episode, 8 artist, 9 album, 10 track, 12 extra/trailer, 13 photo, 15 playlist, 18 collection) are widely used in scripts but I could not find a source that lists them; treat as unverified.

### Gaps
- No authoritative, complete published schema of `com.plexapp.plugins.library.db` was found (full column lists for `metadata_items`, `media_items`, `media_streams`, `library_sections`, `tags`/`taggings` etc.). The best verification route is `sqlite3 ... .schema` on a live install.
- The `metadata_type` numeric mapping could not be sourced.
- The official hardware-accelerated-streaming article returned HTTP 403 to the fetcher; findings above come from the HDR-to-SDR article as summarized in search results and a forum mirror.
- I found no primary Plex source confirming DASH vs HLS selection rules for the universal transcoder (community knowledge: `protocol=dash` is used by Plex Web/desktop and `protocol=hls` by most TV/mobile apps; not verified here).
- Current (2026) Plex Transcoder binary names and whether the FFmpeg 6.1 re-fork has shipped to stable could not be confirmed; the preview thread only confirms 1.42.1.x pre-alpha builds in mid-2025 and transcoder beta threads active into February 2026.

## Key Question 1: What does Plex's client capability/profile system look like compared with Jellyfin's DeviceProfile, and what lessons does it offer for a new server design?

### Takeaway
Plex uses server-side XML client profiles (`Resources/Profiles/*.xml`) matched by HTTP headers/DLNA device descriptions, which native Plex apps *augment* at runtime through the `X-Plex-Client-Profile-Extra` header with directives (e.g. `add-transcode-target(...)`, `append-transcode-target-audio-codec(...)`, `add-limitation(...)`); for native apps the client makes the direct-play/direct-stream/transcode decision before asking the server. Jellyfin's `DeviceProfile` JSON (`DirectPlayProfiles`, `TranscodingProfiles`, `CodecProfiles` with `Conditions`, `SubtitleProfiles`) is structurally the same idea sent in the `PlaybackInfo` POST, but the server makes the decision.

### Cited Findings
- Profile XML structure: root `<Client name="...">` (name must equal file name); `Identification` with `Header name="..." substring|regex` (multiple Headers are ORed) and `DeviceDescription` (FriendlyName, ModelName, ModelNumber, ModelUrl, ModelDescription, Manufacturer, ManufacturerUrl, SerialNumber; ANDed); `TranscodeTargets` holding `VideoProfile protocol="http|slss|hls" container codec audioCodec context` (with `Setting` children such as `VideoEncodeFlags`, `SubtitleSize`, `AudioSyncFlags`, `MpegtsM2tsMode`), `MusicProfile container codec`, `PhotoProfile container`; `DirectPlayProfiles` with `VideoProfile container codec audioCodec` (comma-separated lists) and `PhotoProfile`; `CodecProfiles` with `VideoCodec`/`VideoAudioCodec`/`MusicCodec name="..."` containing `Limitations` of type `Match`, `NotMatch`, `UpperBound`, `LowerBound` on names like `video.width`, `video.height`, `video.bitrate`, `video.frameRate`, `video.videoFrameRate`, `video.bitDepth`, `audio.channels`, `audio.profile`, `part.size`; `ContainerProfiles` (`VideoContainer`/`MusicContainer`/`PhotoContainer` with Limitations, e.g. `<Match name="part.has64bitOffsets" value="0" />`); `DlnaMediaProfiles` (`DlnaVideoProfile container codec audioCodec pn mimeType extension`, evaluated in order, first match wins); profile-level `<Setting name=... value=.../>` such as `OnlyPlainVideoItems`, `OnlyStorageFolders`, `IgnoreTranscodeByteRangeRequests`, `TimelineBufferOffset`, `IconResolution`, `AlbumArtResolution`, `AlbumArtPN`. System profiles live in the install's `Resources/Profiles` and are overwritten on update; user profiles in `Profiles/` under the PMS data dir override by file name — [Plex forums: Writing profiles for DLNA devices](https://forums.plex.tv/t/writing-profiles-for-dlna-devices/38060)
- `X-Plex-Client-Profile-Extra` is parsed server-side by a `ClientProfileExtra` parser; log lines show it rejecting an `append-transcode-target-audio-codec` directive for a "missing protocol parameter" and then falling back to an augmented "Web" profile — [Plex forums: Speeding up centos VM](https://forums.plex.tv/t/speeding-up-centos-vm/357390)
- Community explanation (OttoKerner, Aug 2023, long-time forum volunteer, not identified as staff): native Plex clients start from a generic basic profile; the app queries the hardware for capabilities or looks up its device class in an internal table and uses that to augment the basic profile, so manual XML profiles generally no longer need changes. The augmented-profile mechanism "appears to be under NDA" with no central public reference — [Plex forums: Client Profiles still relevant?](https://forums.plex.tv/t/client-profiles-still-relevant/849312)
- A developer post says profiles mainly matter for DLNA clients; for Plex's own apps the client makes the direct play / transcode decision before sending the request, so a profile cannot change whether a native app transcodes — [Plex forums: Why does H265 video get transcoded when only audio (EAC3) is incompatible?](https://forums.plex.tv/t/why-does-h265-video-get-transcoded-when-only-audio-eac3-is-incompatible/781159.md)
- Users report a "PS5 Player using 'Generic Player'" profile (Dec 2025) and ask "Are custom profiles dead?" — [Plex forums: Client Profiles still relevant? (related topics)](https://forums.plex.tv/t/client-profiles-still-relevant/849312); [Plex forums: Are custom profiles dead?](https://forums.plex.tv/t/are-custom-profiles-dead/774526)
- The decision endpoint family is `/video/:/transcode/universal/...` with parameters `directPlay`, `directStream`, `protocol`, `videoResolution` passed by the web client — [Plex forums: transcoding direct play video resolution bitrates](https://forums.plex.tv/t/transcoding-direct-play-video-resolution-bitrates-etc/189708.md)

### Inferences
- Both systems express the same three concepts: (1) what the client can direct play (container x video codec x audio codec), (2) per-codec limitation predicates (width/height/bitrate/bitDepth/level/channels), (3) what the server should transcode *to* (protocol + container + codecs). Plex adds a fourth: *identification* (header/DLNA regex) so the server can pick a profile for clients that never declare one. Jellyfin instead requires every client to POST its full `DeviceProfile` with `PlaybackInfo` (no server-side registry), which is simpler to reason about and version but puts the burden on every client implementer.
- The lesson from Plex: a server-side profile registry rots (hidden under NDA, "generic player" fallbacks, DLNA-era XML) and an undocumented header DSL (`X-Plex-Client-Profile-Extra`) is fragile (parser rejections at runtime, silent fallback to "Web"). The lesson from Jellyfin: a declarative JSON profile posted per playback is auditable, but Jellyfin clients historically shipped wrong profiles and the server's `StreamBuilder` had to grow heuristics. A new server should (a) make the client's declared profile the source of truth, (b) version the profile schema, (c) return the *reason* for each decision in the response (Plex only logs "reached decision" to debug logs; this is the single most-requested diagnostic), and (d) include subtitle capabilities (`SubtitleProfiles` in Jellyfin: `Embed`/`External`/`Hls`/`Encode` per format) as a first-class axis because ASS is the common failure case.
- Plex native apps deciding client-side means server rules can't force a transcode for a broken device (the Samsung-direct-play complaints); server-authoritative decisions (Jellyfin style) are preferable for a server whose owner wants control.

### Gaps
- No public documentation of the full `X-Plex-Client-Profile-Extra` directive grammar was found; the linked "X-Plex-Client-Profile-Extra Documentation" forum thread was not fetched. The known directive names come only from log lines and secondhand posts.

## Key Question 2: How does Plex handle ASS subtitles during direct play on Android TV and when transcoding? Does Plex burn-in preserve styling?

### Takeaway
On Android/Android TV (ExoPlayer-based), Plex has for years been unable to direct play ASS/SSA with styling: the default behaviour is to transcode video and burn the subtitles in (which preserves ASS styling since the transcoder renders them, but is single-threaded and ends direct play); the "Burn Subtitles = Image Formats Only" workaround lets ASS direct play/stream but drops positioning/colour/fonts. In 2025–2026 Plex removed libmpv from its mobile and Apple TV apps, and as of September–October 2026 users report ASS font loading and complex styling are broken there too; Plex HTPC/Desktop (libmpv) remains the only first-party client that renders ASS natively.

### Cited Findings
- 2021 Plex forum reply: direct play of SSA/ASS is not supported on Android because of an ExoPlayer limitation; you have to transcode. Plex staff said they were working on transcoding audio while direct-playing subtitles without transcoding video, that mpv "would not solve this", and that ASS support was basic and required "Burn Subtitle" set to "Image Formats Only" — [Plex forums: Embedded Subtitles (ASS) forces transcoding with certain clients](https://forums.plex.tv/t/embedded-subtitles-ass-forces-transcoding-with-certain-clients/706266.md)
- 2022: Plex Android TV (incl. Nvidia Shield) direct plays PGS, VOBSUB and SRT even while video/audio transcode; "Direct playing of ASS subtitles is in the works" with a sideloaded test build; with "Image Formats Only", ASS will direct play/direct stream but "formatting information such as position and color will be lost" — [Plex forums: Subtitles slowing down transcoding?](https://forums.plex.tv/t/subtitles-slowing-down-transcoding/800198.md); [Plex forums: Plex ASS subtitle support](https://forums.plex.tv/t/plex-ass-subtitle-support/299268)
- Another user: ASS subtitles on Android TV "still result in a video transcode and subtitle burn", and switching Burn Subtitles from Automatic to Image Only lets ASS direct play but any formatting (location, colour) is ignored — [Plex forums: Are custom profiles dead?](https://forums.plex.tv/t/are-custom-profiles-dead/774526/8); [Plex forums: Diagnosing transcoding issues](https://forums.plex.tv/t/diagnosing-transcoding-issues/765294/25)
- The Android client uses ExoPlayer, whose ASS support is very limited; Plex for Windows (mpv underneath) direct plays ASS — [Plex forums: Plex ASS subtitle support](https://forums.plex.tv/t/plex-ass-subtitle-support/299268); [Plex forums: Subtitles transcoded from SRT to ASS](https://forums.plex.tv/t/subtitles-transcoded-from-srt-to-ass/818680.md)
- 2022 Shield report: when transcoding video, Plex for Android TV ignores the user's subtitle colour setting unless "Override included subtitle styling" is on (burned subs show white otherwise) — [Plex forums: Subtitle default style being overridden on Shield](https://forums.plex.tv/t/subtitle-default-style-being-overridden-on-shield/802207.md)
- Casting from Android to Chromecast converts ASS to WebVTT and loses styling and placement; the old app could direct play these or burn them when transcoding — [Plex forums: Subtitle issues when casting from Android](https://forums.plex.tv/t/subtitle-issues-when-casting-from-android/922901.md)
- A long-standing user feature request "[implemented] Ass/ssa subtitle support" exists — [Plex forums: Ass/ssa subtitle support](https://forums.plex.tv/t/implemented-ass-ssa-subtitle-support/543947)
- September 23, 2026 thread "Plans to bring back subtitle support?": Plex dropped libmpv on mobile "last year"; without it ASS fonts don't load and complex styling stutters on iOS; the same change arrived on Apple TV in a recent update; workaround is "burn subtitles = always" (ends direct play), converting to SRT, reverting to tvOS app 8.45, or using third-party clients Plezy (mpv-based) and Infuse. Staff (Atomatth, Sept 24, 2026) added the thread to an existing open issue. Oct 13, 2026 post: simple ASS renders on Apple TV but advanced positioning/animation breaks and renders slowly — [Plex forums: Plans to bring back subtitle support?](https://forums.plex.tv/t/plans-to-bring-back-subtitle-support/943302)
- Plex HTPC uses libmpv as a separate DLL (`mpv-2.dll` on Windows) because mpv is LGPL and must be substitutable; users swap in newer libmpv builds and customise via `%LOCALAPPDATA%\Plex HTPC\mpv.conf`; on Linux the negativo17 packages use MPV as the main player; a Jan 2025 SVP wiki note says Plex HTPC lagged newer mpv — [Plex forums: Plex HTPC Guide (Windows)](https://forums.plex.tv/t/plex-htpc-guide-windows/857522.md); [SVP wiki: Plex](https://svp-team.com/wiki/SVP:Plex); [negativo17 Plex HTPC packages](https://negativo17.org/category/plex-media-server/)
- Forum thread "[Android] switch from ExoPlayer to mpv" exists as a user request (unimplemented) — [Plex forums](https://forums.plex.tv/t/android-switch-from-exoplayer-to-mpv/412965)
- Subtitle burning is single-threaded — [Plex forums: Subtitles slowing down transcoding?](https://forums.plex.tv/t/subtitles-slowing-down-transcoding/800198.md)

### Inferences
- Plex's burn-in path for ASS renders the subtitle track inside the transcoder, so styling, fonts (attachments) and positioning survive *when the video is transcoded*; that matches user reports that burn-in "works" but is costly. The styling loss happens only when Plex converts ASS to a text format (WebVTT for Chromecast, "Image Formats Only" direct play on ExoPlayer) rather than burning.
- Plex's ASS story has gone backwards in 2025–2026 on iOS/tvOS because of the libmpv removal; only Plex HTPC (libmpv) and third-party mpv-based clients (Plezy, plex-mpv-shim) render ASS faithfully. For an anime-oriented server, this is the strongest argument for a client strategy built around libass (mpv on desktop/HTPC, libass-in-ExoPlayer or a native renderer on Android TV) and for a server-side "burn with libass, preserving attached fonts" fallback that is explicitly chosen per client capability.
- Because the Plex client decides direct-play vs transcode itself, the only server-side levers are the per-client "Burn Subtitles" setting and forcing transcode; a new server should let the server decide subtitle delivery mode per `SubtitleProfile` (embed / external sidecar / burn), the way Jellyfin does, so ExoPlayer clients can still direct-play video while the server burns or re-muxes subtitles only.

### Gaps
- No 2025–2026 primary statement from Plex about the current ASS status on **Android TV** specifically; the latest confirmed material for Android TV is 2022 ("in the works", test build). It is unknown whether the ExoPlayer ASS direct-play work ever shipped to production.
- No Plex documentation of *how* burn-in is implemented (whether the transcoder fork uses libass and honours MKV font attachments); the inference above is from user-observed behaviour.
- Plex HTPC's exact libmpv version in 2026 and whether Plex Desktop (the non-HTPC desktop app) still uses mpv were not confirmed.

## Key Question 3: How does the plex.tv-centric account model work, and what would a self-hosted replacement need (local accounts plus optional federated auth)?

### Takeaway
Identity is entirely cloud-side: a client gets a token via a PIN/OAuth-style flow against `plex.tv/api/v2/pins` + `app.plex.tv/auth`, the server is "claimed" by an account, sharing/Plex Home/managed users are plex.tv objects, and since April 29, 2025 even playback of your own media over the internet requires a Plex Pass (server owner) or Remote Watch Pass (user), rolled out to Roku in Nov 2025 and to other TV apps and third-party API clients in 2026. A self-hosted replacement needs a local user store with per-device tokens, a device-code/PIN flow for TV clients, library-level sharing/restrictions, and an optional OIDC federation layer, while never gating LAN or WAN playback on a cloud entitlement.

### Cited Findings
- Documented PIN flow (Plex forums "Authenticating with Plex", official how-to): generate and persist a client identifier; verify a stored token with `GET https://plex.tv/api/v2/user` (200 valid, 401 invalid, anything else is an error not an invalidation); `POST https://plex.tv/api/v2/pins` with `strong=true`, `X-Plex-Product`, `X-Plex-Client-Identifier`; send the user to `https://app.plex.tv/auth#?clientID=<clientIdentifier>&code=<pinCode>&forwardUrl=<url>&context%5Bdevice%5D%5Bproduct%5D=<appName>`; then either forward-and-check `GET https://plex.tv/api/v2/pins/<pinID>` (with `code` and `X-Plex-Client-Identifier`) or poll about once per second until `authToken` is non-null or the PIN expires; token lifetime is not stated — [Plex forums: Authenticating with Plex](https://forums.plex.tv/t/authenticating-with-plex/609370)
- python-plexapi's plex.tv surface: signin `/api/v2/users/signin`; `/api/v2/pins` (strong); `/api/v2/user`; `/api/v2/ping`; resources `/api/v2/resources?includeHttps=1&includeRelay=1&includeIPv6=1`; `devices.xml`; users `/api/users/`; invites `/api/invites/requests|requested`; shared servers `/api/servers/{machineId}/shared_servers[/{serverId}]`; sharing filters `/api/v2/sharings/{userId}`; Plex Home `/api/home/users`, `?title=` to create, `/api/home/users/{id}/switch`, restricted users `/api/v2/home/users/restricted/{userId}`; claim token `/api/claim/token.json`; webhooks `/api/v2/user/webhooks`; newer JWT login via `clients.plex.tv/api/v2/pins` and `/api/v2/auth` — [python-plexapi myplex.py](https://raw.githubusercontent.com/pkkid/python-plexapi/master/plexapi/myplex.py)
- March 19, 2025 announcement: remote playback no longer free from April 29, 2025; Plex Pass on the server owner covers all users of that server; new Remote Watch Pass at $1.99/month or $19.99/year for users without Plex Pass; Plex Pass price rose from $5.99 to $6.99 monthly and $49.99 to $69.99 yearly — [BetaNews, 2025-03-19](https://betanews.com/2025/03/19/plex-2025-price-changes-remote-streaming-new-subscription/); [9to5Mac, 2025-03-19](https://9to5mac.com/2025/03/19/plex-price-increase-remote-streaming-changes/)
- November 19, 2025 Plex forum post (PlexInfo): the requirement reaches the Roku app the following week; the same requirement reaches other TV apps (Fire TV, Apple TV, Android TV, ...) and third-party clients that use the API for remote streaming in 2026; the model rolled out to mobile first; promo 40% off Plex Pass through Dec 1, 2025 — [Plex forums: Changes Coming to Remote Streaming on Roku](https://forums.plex.tv/t/changes-coming-to-remote-streaming-on-roku/933671/1); [BetaNews, 2025-11-26](https://betanews.com/2025/11/26/plex-is-clamping-down-on-free-remote-streaming/)
- Relay fallback is capped at 1 Mbps (free) / 2 Mbps (Plex Pass) and is used whenever the server is not directly reachable (no port-forward of 32400) — [Plex forums: Remote Access bandwidth limit](https://forums.plex.tv/t/remote-access-bandwidth-limit/586227)
- Webhooks and hardware transcoding are Plex Pass features — [support.plex.tv: Webhooks](https://support.plex.tv/articles/115002267687-webhooks/); [Plex forums: Server/Transcoding/PlexPass](https://forums.plex.tv/t/server-transcoding-plexpass/816242.md)
- Tautulli treats a sustained websocket disconnect as a possible expired plex.tv token (`plextv.notify_token_expired()`) — [Tautulli web_socket.py](https://raw.githubusercontent.com/Tautulli/Tautulli/master/plexpy/web_socket.py)

### Inferences
- The entitlement enforcement for remote streaming necessarily depends on the server consulting plex.tv (the server must know whether the *owner* has Plex Pass or the *user* has Remote Watch Pass, and whether a session is "local"); the webhook payload's `Player.local` flag shows the server already classifies sessions as local vs remote. This is exactly the dependency a self-hosted server must not have: with plex.tv unreachable, Plex cannot even authenticate a LAN user (the token verification endpoint is cloud-only, and the server-side "allow without auth on LAN" list is the only escape hatch).
- A self-hosted replacement should provide: (1) local accounts with password/passkey and per-device long-lived tokens, (2) a device-code/PIN flow identical in UX to `app.plex.tv/auth` but served by the server itself (so TV clients type a code on a phone), (3) a "Home"-style profile concept (managed child profiles without separate credentials, PIN-switchable), (4) library-scoped sharing with content filters (Plex's `/api/v2/sharings/{userId}` filters: ratings, labels), (5) optional OIDC/OAuth federation (so a hosted identity provider can be used but is never required), and (6) a watchlist that lives on the server with optional sync to external services. Jellyfin already has (1), (2) via Quick Connect (`/QuickConnect/Initiate`, `/QuickConnect/Connect`, `/Users/AuthenticateWithQuickConnect`), and (4).
- Because Sonarr and Tautulli identify Plex users by plex.tv numeric ids and verify server access via `/api/users` on plex.tv, any new server that wants "Plex-compatible" integrations would have to emulate plex.tv endpoints too, not just PMS; targeting the Jellyfin/Emby contract is far cheaper.

### Gaps
- The exact server-side mechanism for local-vs-remote classification and the entitlement check (e.g. what happens when plex.tv is unreachable, how "Treat WAN IP as LAN"/allowed networks interact) could not be sourced; the reddit thread with the Tautulli developer's explanation was unreachable (DNS failure), and the Roku announcement does not describe enforcement.
- Whether the 2026 rollout to third-party API clients (Infuse, Tautulli-style tools) has completed by October 2026 was not confirmed.
- The official Relay support article returned 403; bandwidth caps are cited via forum quotes of that article.
- Plex token lifetime/expiry policy is not documented in the auth how-to.

## Key Question 4: What do Sonarr/Radarr/Tautulli need from Plex, and which contract should a new server target?

### Takeaway
Sonarr/Radarr only need `/library/sections/{id}/refresh[?path=]` with a plex.tv-issued token; Tautulli needs the `/:/websockets/notifications` stream plus `/status/sessions`-style polling. The Jellyfin/Emby contract is the smaller, fully documented one to target.

### Cited Findings

**Sonarr/Radarr <-> Plex**
- Servarr wiki: the "Plex Media Server" connection pushes an update so Plex knows a new/upgraded episode exists; "rarely needed and is only required if Plex is unable to watch the file system for changes"; warning that it "may trigger a full library scan" of the series' library/root folder; recommended alternative is Plex's own filesystem watching or `plexautoscan`. Connection triggers include On Import, On Upgrade, On Rename, On Series Delete, On Episode File Delete, On Import Complete, etc. "Plex Watchlist" is an Import List: one list per authenticated Plex user — [Servarr wiki: Sonarr supported](https://raw.githubusercontent.com/Servarr/Wiki/master/sonarr/supported.md); [Servarr wiki: Sonarr settings](https://raw.githubusercontent.com/Servarr/Wiki/master/sonarr/settings.md)
- The scan endpoints themselves: `GET /library/sections/{key}/refresh` (whole section) and `GET /library/sections/{key}/refresh?path=<urlencoded path>` (partial); `DELETE` cancels — [python-plexapi library.py](https://raw.githubusercontent.com/pkkid/python-plexapi/master/plexapi/library.py)

**Tautulli <-> Plex**
- Websocket `/:/websockets/notifications` with `X-Plex-Token` header; `playing` / `timeline` / `reachability` notification types; a startup `check_active_sessions(ws_request=True)` reconciliation and token-expiry notification on sustained disconnect — [Tautulli web_socket.py](https://raw.githubusercontent.com/Tautulli/Tautulli/master/plexpy/web_socket.py)
- The same websocket is used by the trakt scrobbler and may require Plex Pass (forum claim, 2014-era) — [Plex forums: Attaching Events To "Now Playing"](https://forums.plex.tv/t/attaching-events-to-now-playing/81228)
- Tautulli can silently stop recording when the PMS URL, token, or Docker bridge changes — [ElfHosted Tautulli page](https://store.elfhosted.com/product/tautulli/)

### Inferences
- Sonarr/Radarr need only `/library/sections/{id}/refresh?path=` (Plex) or `/Library/Media/Updated`-style endpoints (Jellyfin, not covered here). Targeting the Jellyfin/Emby contract is clearly less work and better documented.
- Plex's `includeGuids=1` + `Guid[]` design (multiple external ids per item) is the right model; Jellyfin's `ProviderIds` map is equivalent. A new server should expose both an `/Items`-style JSON listing with provider ids and a path-scoped rescan endpoint, because those two things are what every *arr integration actually consumes.

### Gaps
- Radarr's Plex connection was not separately researched; Servarr's Sonarr pages were used. The Sonarr wiki pages do not enumerate the Plex connection fields (host/port/SSL/"Authenticate with Plex.tv"/Update Library) or Jellyfin fields; those are only visible in the apps' UIs.
- Tautulli's `activity_handler.py` (the fields it reads from `PlaySessionStateNotification`: `sessionKey`, `state`, `ratingKey`, `viewOffset`) was not fetched; only `web_socket.py` was.
- The `/:/timeline` client-reporting endpoint and `/:/scrobble` were not documented by any fetched primary source in this run (plexapi.dev's reference pages were not reachable through the landing page).

## Key Question 5: What are the agreed strengths of Plex's architecture and its weaknesses?

### Takeaway
Strengths that recur in sources: a fast single-file SQLite library with FTS and guid-keyed watch state, a mature transcode/decision engine with HW tone mapping and a custom FFmpeg fork, built-in cloud metadata agents that removed the need for third-party plugins, and the broadest first-party client ecosystem. Weaknesses: closed source with undocumented internals (profiles under NDA, no fork source), hard plex.tv dependency for auth/sharing/remote access, an EOL Python 2.7 legacy agent/scanner framework still carrying anime (HAMA) users, a 2025 paywall on remote streaming plus Plex Pass price increases, and 2025–2026 regressions in ASS subtitle rendering after dropping libmpv.

### Cited Findings
- Strength, decision engine and HW pipeline: HW tone mapping on Intel Kaby Lake+/NVIDIA 470.141.03+; FFmpeg 6.1 re-fork with performance gains and faster future updates — [support.plex.tv: HDR to SDR tone mapping](https://support.plex.tv/articles/hdr-to-sdr-tone-mapping/); [Plex forums: Transcoder Upgrade Forum Preview](https://forums.plex.tv/t/transcoder-upgrade-forum-preview/924241)
- Strength, built-in agents: 2024 community consensus is to use Plex Series / Plex Movie and that third-party agents are unnecessary for most users — [lemm.ee](https://lemm.ee/comment/13793204)
- Strength, integration ecosystem: Sonarr (Plex connection + Plex Watchlist import list) and Tautulli both have first-class Plex support — [Servarr wiki supported](https://raw.githubusercontent.com/Servarr/Wiki/master/sonarr/supported.md); [Tautulli web_socket.py](https://raw.githubusercontent.com/Tautulli/Tautulli/master/plexpy/web_socket.py)
- Strength, DB: single SQLite file with FTS4 triggers and a dumpable per-account view-state table — [Plex forums: moving media HowTo](https://forums.plex.tv/t/howto-plex-database-modification-moving-media-the-right-wrong-way/126701); [support.plex.tv: move viewstate](https://support.plex.tv/articles/201154527-move-viewstate-ratings-from-one-install-to-another/)
- Weakness, DB growth: users report slow library performance as the DB grows — [Plex forums](https://forums.plex.tv/t/slow-library-performance-due-to-increasingly-growing-database/740511/1)
- Weakness, closed/undocumented: client-profile augmentation "appears to be under NDA"; no public source for the ffmpeg fork since a 2016 tarball; dev.plexapp.com gone and plugin framework EOL — [Plex forums: Client Profiles still relevant?](https://forums.plex.tv/t/client-profiles-still-relevant/849312); [Plex forums: transcoder source LGPL](https://forums.plex.tv/t/plex-new-transcoder-source-code-lgpl/179121); [Plex forums: dev.plexapp.com](https://forums.plex.tv/t/what-happened-to-dev-plexapp-com/849957.md)
- Weakness, legacy framework: Python 2.7.x EOL, HTTPS breakage, legacy agents hidden since recent releases but still needed by some users (Feb 2026) — [Plex forums: Missing agents and scanner files](https://forums.plex.tv/t/missing-agents-and-scanner-files/936305.md); [Plex forums: HTTPS broken](https://forums.plex.tv/t/https-broken/216635)
- Weakness, pricing/cloud gating: remote streaming paywalled from April 29, 2025; Plex Pass $6.99/mo / $69.99/yr; Remote Watch Pass $1.99/mo; rollout to all TV apps and third-party clients in 2026; Relay capped at 1–2 Mbps; webhooks and HW transcoding Plex Pass-only — [BetaNews 2025-03-19](https://betanews.com/2025/03/19/plex-2025-price-changes-remote-streaming-new-subscription/); [Plex forums: Roku remote streaming](https://forums.plex.tv/t/changes-coming-to-remote-streaming-on-roku/933671/1); [support.plex.tv: Webhooks](https://support.plex.tv/articles/115002267687-webhooks/)
- Weakness, subtitles/clients: ASS rendering regressed on iOS/tvOS after libmpv removal (Sept–Oct 2026 reports); Android TV still burns ASS; casting loses styling — [Plex forums: Plans to bring back subtitle support?](https://forums.plex.tv/t/plans-to-bring-back-subtitle-support/943302); [Plex forums: casting from Android](https://forums.plex.tv/t/subtitle-issues-when-casting-from-android/922901.md)
- Weakness, transcoder regressions: TrueHD transcodes broke in 1.43.3 via the EAE handoff (2026) — [Plex forums: TrueHD/MLP audio transcodes fail](https://forums.plex.tv/t/truehd-mlp-audio-transcodes-fail-transcoder-writes-mlp-files-into-eae/940690)

### Inferences
- For a from-scratch server aimed at anime/ASS-heavy libraries, Plex's lessons are: keep the library DB simple and single-file (SQLite with FTS works at Plex scale) but key user state by stable external GUIDs; make decision logic server-authoritative and *explainable* in API responses; keep metadata providers out of process; ship stock FFmpeg + libass and treat ASS delivery (direct play with fonts, sidecar, or burn) as a declared client capability; and never require a cloud account for LAN or WAN playback. Jellyfin already does most of these; Plex's remaining edge is client breadth (Roku, smart TVs) and polished hardware pipelines (tone mapping, EAE audio), not architecture.

### Gaps
- No independent benchmark comparing Plex vs Jellyfin library scan or query performance was found; "fast library DB" is a community reputation, not a measured claim in the fetched sources.
- Plex telemetry specifics (what is sent to plex.tv, opt-out scope) were not researched in this run.
