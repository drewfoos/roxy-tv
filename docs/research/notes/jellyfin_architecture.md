# Jellyfin Server Internals: Architecture Blueprint (as of October 2026; 10.10 / 10.11.x; next major = "12.0", not 11)

Scope note on versions: There is no "Jellyfin 11". The current stable line as of mid-2026 is 10.11.x (10.11.0 shipped October 2025; 10.11.11 was announced 6 June 2026). In the January 2026 "State of the Fin" the team said it is considering dropping the "10." prefix so the next major release would be 12.0 (web client work is labelled "vNext (aka 10.12 / 12.0)"), but "nothing has been finalized yet". The typescript SDK already maps SDK 1.0.0 to "Jellyfin 12.x". Everything below cites 10.9/10.10/10.11 and master-branch source as of the research date.

## Q0. Tech stack, fork history, repository layout

### Takeaway
Jellyfin is a C#/.NET monolith (currently built with the .NET 10 SDK on master; .NET 8 for 10.9/10.10, .NET 9 for 10.11) descended from Emby 3.5.2, with an ASP.NET Core/Kestrel API layer, EF Core + SQLite persistence (fully migrated in 10.11), and an external ffmpeg/ffprobe for all media work. The solution is split into ~20 projects whose "Emby.*" / "MediaBrowser.*" names are the inherited Emby layout and "Jellyfin.*" names are the post-fork additions.

### Cited Findings
- Jellyfin "is descended from Emby's 3.5.2 release and ported to the .NET platform to enable full cross-platform support"; building requires the .NET 10 SDK on master; ffmpeg must be installed separately; the web client is a separate repo (jellyfin-web); license GPL-2.0 — [GitHub README](https://github.com/jellyfin/jellyfin)
- Project started "in early December 2018 primarily as a result of Emby's decision to take their next release (4.x) closed-source"; reasons cited: earlier GPL violations, paywall for free users in an early 3.x, removal/hiding of client and server code, limited openness to contributions — [jellyfin.org About](https://jellyfin.org/docs/general/about)
- Wikipedia dates the fork to 8 Dec 2018; the only release using Emby numbering was 3.5.2-5 (30 Dec 2018); Jellyfin's own numbering began with 10.0.0 in January 2019 — [Wikipedia: Jellyfin](https://Www.Wikipedia.org/wiki/Jellyfin)
- Contributing docs describe the server as "built using .NET 9 and C#" (10.11 era) and the web client as a browser client also wrapped by several native clients; `master` is the dev branch; PRs need two core reviews — [Development docs](https://jellyfin.org/docs/general/contributing/development/)
- 10.9.0 upgraded the server to .NET 8, raised min FFmpeg from 4.0 to 4.4 (official builds ship 6.0.1), moved DLNA out of core into an optional plugin, added in-process restart, SQLite connection pooling, HappyEyeballs dual-stack — [10.9.0 release post](https://jellyfin.org/posts/jellyfin-release-10.9.0)
- 10.10.0: FFmpeg based on upstream 7.0; server refuses to start if ffmpeg missing/wrong version (bypassable); media segments storage; keyframe-only trickplay extraction (~100x faster); network library paths removed; Raspberry Pi V4L2 transcoding deprecated; armhf deprecation announced — [10.10.0 release post](https://jellyfin.org/posts/jellyfin-release-10.10.0)
- 10.11.0: FFmpeg 7.1; ARM32 fully removed; internal TLS deprecated for removal in 10.12; "old authorization methods" planned for removal in 10.12; server may return 503 + Retry-After during startup — [10.11.0 release post](https://jellyfin.org/posts/jellyfin-release-10.11.0)

- Newer code lives under `src/`: e.g. `src/Jellyfin.Database/Jellyfin.Database.Implementations/Entities/BaseItemEntity.cs` and `.../Entities/User.cs` — [BaseItemEntity.cs](https://github.com/jellyfin/jellyfin/blob/master/src/Jellyfin.Database/Jellyfin.Database.Implementations/Entities/BaseItemEntity.cs); [User.cs](https://github.com/jellyfin/jellyfin/blob/master/src/Jellyfin.Database/Jellyfin.Database.Implementations/Entities/User.cs)

### Inferences
- The split `MediaBrowser.Controller` (interfaces) / `Emby.Server.Implementations` (implementations) / `MediaBrowser.Model` (DTOs shared with clients) is the Emby-era layering; `Jellyfin.Server.Implementations` was created to host EF Core-backed replacements, so the codebase currently has two parallel "implementations" projects — a visible artifact of the incremental migration.
- Everything that touches media (probe, transcode, image extraction, subtitle extraction, attachment dump) shells out to ffmpeg/ffprobe; nothing links libav directly. A from-scratch clone could do the same and inherit the same process-management complexity (timeouts, stderr draining, kill timers).

### Gaps
- No official document describes which specific files are "unchanged Emby code" vs rewritten; the only official architecture statements are the source-tree page and release-post remarks about "spaghetti" DB code.
- I did not verify whether a release newer than 10.11.11 (June 2026) exists as of October 2026.

## Q1. Core domain models (BaseItem hierarchy, MediaSourceInfo, MediaStream, UserItemData) and how they are persisted

### Takeaway
`BaseItem` subclasses (Movie, Series, Season, Episode, Audio, Folder, CollectionFolder, UserRootFolder, AggregateFolder, Person/Genre/Studio "ItemByName" types…) are persisted as a single `BaseItemEntity` table row whose `Type` column holds the CLR type name and whose `Data` column holds a serialized blob for type-specific fields, with normalized side tables for media streams, chapters, provider IDs, images, people, item values (genres/tags/studios), ancestor relations, linked children, trickplay info and per-user data. `MediaStream` (ffprobe-derived per-track info incl. HDR/DoVi classification and subtitle-format predicates) is the single most important model for playback decisions.

- User data write path: `SessionManager.OnPlaybackStart` increments `PlayCount`, sets `LastPlayedDate`, and sets `Played` only for items that support played status but not resume; `OnPlaybackProgress` writes via `_userDataManager` (`UpdatePlayState` with `PositionTicks`) only when not automated; `OnPlaybackStopped` with no position assumes completion (PlayCount++, Played=true, position 0) and saves with `UserDataSaveReason.PlaybackFinished`; `PropagatePlayedState` copies Played across alternate versions of a `Video`; `UpdatePlaybackSettings` stores audio/subtitle indexes if the user's remember-selection flags allow — [SessionManager.cs](https://github.com/jellyfin/jellyfin/blob/master/Emby.Server.Implementations/Session/SessionManager.cs)
- Pre-10.11 there was "effectively zero centralization of the database management functionality into an ORM"; 10.11 "creates proper relational cross-references in the database, including foreign keys" and moves data from `library.db` into `jellyfin.db` — [10.11.0 release post](https://jellyfin.org/posts/jellyfin-release-10.11.0)

### Inferences
- The `Type` + `Data` design is a hybrid table-per-hierarchy + document store: hot/filterable fields are columns, the rest is serialized. The `InternalId` on User ("temporary ID corresponding to the user's index in the library database") is a leftover from when users lived in a separate DB from items.
- `IsTextFormat` is the one place the whole server decides "text vs image subtitle"; ASS/SSA are text. Any clone must get this classification right because it gates extraction, HLS delivery and burn-in.

### Gaps
- The exact serialized format of `BaseItemEntity.Data` (JSON vs other) and the full list of `BaseItem` subclasses were not confirmed from the fetched excerpts.
- `UserData` entity columns (Rating, PlaybackPositionTicks, PlayCount, IsFavorite, Played, AudioStreamIndex, SubtitleStreamIndex, Likes, LastPlayedDate) were not fetched; they are referenced indirectly via `SessionManager` and `BaseItemEntity.UserData`.
- `PermissionKind`/`PreferenceKind` enum values were not confirmed.

## Q2. Library scan: file walk, resolvers, naming (Emby.Naming), multi-version, extras, anime naming, ordered chapters

### Takeaway
A scan is a scheduled task (`RefreshMediaLibraryTask`) that validates top-level `CollectionFolder`s, then recursively calls `Folder.ValidateChildren`; each path goes through a priority-ordered chain of `IItemResolver`s (with `IMultiItemResolver`s used to group multi-version/multi-part files) after `IResolverIgnoreRule` filtering; `Emby.Naming` supplies regex-driven episode/season/stacking/extras/flag parsing. Multiple versions are linked via `PrimaryVersionId`/`LocalAlternateVersions`; extras via `OwnerId`/`ExtraType`. Absolute anime numbering is parsed by regex but season/episode mapping is left to metadata providers; MKV ordered chapters are not supported (open feature request).

### Cited Findings
- `ValidateMediaLibrary` queues `RefreshMediaLibraryTask` via `_taskManager.CancelIfRunningAndQueue`; `ValidateMediaLibraryInternal` sets `IsScanRunning`, clears the ignore-rule cache, stops `LibraryMonitor`, runs `PerformLibraryValidation` = `ValidateTopLibraryFolders` → `RootFolder.ValidateChildren(recursive: true)` (~96% of progress) → `RunPostScanTasks` (`ILibraryPostScanTask`s, then `_persistenceService.UpdateInheritedValues()`); `ValidateTopLibraryFolders` refreshes `AggregateFolder` and `UserRootFolder` and deletes `CollectionFolder` records whose directories vanished — [LibraryManager.cs](https://github.com/jellyfin/jellyfin/blob/master/Emby.Server.Implementations/Library/LibraryManager.cs)
- `AddParts` orders `IItemResolver` by `Priority`, collects `IMultiItemResolver` and `IResolverIgnoreRule`; `ResolvePath` builds `ItemResolveArgs` (Parent, FileInfo, CollectionType, LibraryOptions, FileSystemChildren…), applies `IgnoreFile`, gathers children via `FileData.GetFilteredFileSystemEntries`; `ResolveItem` takes the first non-null resolver result and `ResolverHelper.SetInitialItemValues` populates it; `ResolvePaths` tries `IMultiItemResolver.ResolveMultiple` first and falls back to per-file `ResolveFileList`; multi-part handled by `SetAdditionalPartsFromStack` using `StackResolver`; alternate versions use `LocalAlternateVersions`/`LinkedAlternateVersions` with `PrimaryVersionId`/`OwnerId`; `DotIgnoreIgnoreRule` is one ignore rule; `.collection` marker files set `CollectionTypeOptions`; `CreateItems` calls `_persistenceService.SaveItems`, registers items in cache, raises `ItemAdded`; `DeleteItem` reassigns primary/alternate versions, removes metadata dirs, deletes file only when `DeleteFileLocation` applies, then `_persistenceService.DeleteItem` — [LibraryManager.cs](https://github.com/jellyfin/jellyfin/blob/master/Emby.Server.Implementations/Library/LibraryManager.cs)
- `Emby.Naming/Common/NamingOptions.cs`: ~60 `VideoFileExtensions` (incl. `.strm`, `.iso`); `StubFileExtensions` = `.disc`; `EpisodeExpressions` tried in order (several `IsOptimistic`): Kodi SxxExx `.*(\\|\/)(?<seriesname>...)?[Ss](?<seasonnumber>[0-9]+)[][ ._-]*[Ee](?<epnumber>[0-9]+)([^\\/]*)$`; "Season N Episode M"; `1x01` `.*(\\|\/)[sS]?(?<seasonnumber>[0-9]+)[xX](?<epnumber>[0-9]+)[^\\\/]*$`; absolute `[Ee]pisode (?<epnumber>[0-9]+)(-(?<endingepnumber>[0-9]+))?`; anime-style `Series - 04` and `[04]` variants; date-based `yyyy.MM.dd`/`yyyy-MM-dd`/`dd.MM.yyyy`; `MultipleEpisodeExpressions` for `S01E01-E02`-style ranges; season-folder fallbacks `[Ss]eason[\._ ](?<seasonnumber>[0-9]+)[\\\/](?<epnumber>[0-9]{1,3})`; `VideoFileStackingRules` `^(?<filename>.*?)(?:(?<=[\]\)\}])|[ _.-]+)[\(\[]?(?<parttype>cd|dvd|part|pt|dis[ck])[ _.-]*(?<number>[0-9]+)[\)\]]?(?:\.[^.]+)?$` plus an `[a-d]` letter variant; `CleanDateTimeRegexes` extract 19xx/20xx years; `CleanStringRegexes` strip `1080p`, `bluray`, `x264/x265`, `HDR`, `WEB-DL`, `proper`, `repack`, `3d/sbs/tab`…; `VideoExtraRules` with `ExtraRuleType` {DirectoryName, Filename, Suffix} — directory names `trailers`, `backdrops` (ThemeVideo), `theme-music`, `behind the scenes`, `deleted scenes`, `interviews`, `scenes`, `samples`, `shorts`, `featurettes`, `extras/extra/other` (Unknown), `clips`; filename rules `trailer`, `sample`, `theme`; suffix rules `-trailer`, `.trailer`, `_trailer`, `- trailer`, `-sample`…, `-scene`, `-clip`, `-interview`, `-behindthescenes`, `-deleted`, `-deletedscene`, `-featurette`, `-short`, `-extra`, `-other`; `SubtitleFileExtensions` `.ass .mks .sami .smi .srt .ssa .sub .sup .vtt`; `LyricFileExtensions` `.lrc .elrc .txt`; `VideoFlagDelimiters` `( ) - . _ [ ]`; media flags `forced/foreign`, `default`, `cc/hi/sdh`; `Format3DRules` `hsbs sbs htab tab fsbs ftab sbs3d mvc` — [NamingOptions.cs](https://github.com/jellyfin/jellyfin/blob/master/Emby.Naming/Common/NamingOptions.cs)
- Official naming rules (shows): `Series Name (year) [metadata provider id]/Season 05/Series Name S01E01.mkv`; don't mix season folders and loose episodes; two-part episodes `S01E01-E02` or `S02E03 Part 1`; provider IDs allowed at season/episode level `S01E01 [provider id].mkv`; specials in `Season 00` with `airsbefore_season`/`airsafter_season`/`airsbefore_episode` NFO fields; multiple versions: same season folder, label after `-`/`.`/`_`/`[ ]` e.g. `Series S01E01 - 1080p.mkv`, resolution labels sort high→low, others alphabetical, first = default; part types `cd dvd part pt disc disk` with number or `a–d` — [Shows naming docs](https://jellyfin.org/docs/general/server/media/shows/)
- Official naming rules (movies): `Movie Name (year) [imdbid-tt...]/Movie Name (year) [imdbid-tt...].mkv`; versions = files in the folder whose names begin exactly with the folder base name + label; `VIDEO_TS`/`BDMV` folders supported but with no multi-version/multi-part/external tracks; `.iso` not supported; local image names `poster/folder/cover/default/movie` (Primary), `backdrop/fanart/background/art/extrafanart`, `banner`, `logo/clearlogo`, `landscape/thumb`; multiple backdrops `backdrop-1.jpg` — [Movies naming docs](https://jellyfin.org/docs/general/server/media/movies/)
- Anime: forum reports that default providers split absolute-numbered series into seasons even with display order set to absolute; suggested fixes are to enable only the one provider that sorts absolute episodes as season 1, or use Shokofin (Shoko Server matches by AniDB hash and supplies structure, so file names need not match) — [Jellyfin forum](https://forum.jellyfin.org/t-absolute-order-detection-with-no-season-id); [Jellyfin forum](https://forum.jellyfin.org/t-absolute-numbering-for-anime?pid=48523); [JellyWatch Shokofin guide](https://jellywatch.app/blog/shokofin-jellyfin-anime-plugin-anidb-complete-guide-2026)
- AniDB "uses only absolute order and has no seasons, so one TV show can map to several AniDB entries" — [FileBot forum](https://www.filebot.net/forums/viewtopic.php?p=44290)
- Official plugin list includes Anilist, Anidb, Anisearch, Kitsu, Shokofin (third-party, ShokoAnime), Ani-Sync — [Plugins docs](https://jellyfin.org/docs/general/server/plugins/)
- MKV ordered chapters / segment linking: open Jellyfin feature request https://features.jellyfin.org/posts/390/support-mkv-ordered-chapters-segment-linking; FFmpeg ticket #3123 remains "new / wish" — [FFmpeg trac #3123](https://fftrac-bg.ffmpeg.org/ticket/3123)
- 10.11: when a file is replaced, the scan prunes chapters, trickplay files, extracted subtitles and attachments so they regenerate — [10.11.0 release post](https://jellyfin.org/posts/jellyfin-release-10.11.0)
- 10.10 removed network (UNC/SMB URL) library paths entirely — [10.10.0 release post](https://jellyfin.org/posts/jellyfin-release-10.10.0)

### Inferences
- Because Jellyfin relies on ffmpeg for demuxing and ffmpeg itself has no ordered-chapter/segment-linking support (ticket open since 2013), Jellyfin cannot implement ordered chapters without either a custom demux layer or client-side stitching. Expect this to remain unsupported.
- Absolute numbering is parsed syntactically (regex gives an `epnumber` with no season), but the semantic mapping to seasons is delegated to whichever metadata provider wins; this is why anime users route through Shoko/AniDB plugins. A clone targeting anime should treat "absolute order" as a first-class series ordering rather than a provider concern.

### Gaps
- `Folder.ValidateChildren`/`RemoveChildren` (the actual add/remove diff logic) and `ItemResolveArgs` were not in the fetched excerpt.
- `EpisodeResolver`/`EpisodePathParser` handling of `IsAbsoluteNumbering` and the series `DisplayOrder` (absolute/dvd/aired) setting was not fetched; only forum evidence of behavior.

## Q3. Metadata fetching: provider manager, local NFO, image providers, plugins

### Takeaway
`ProviderManager` (MediaBrowser.Providers) is a registry of `IMetadataProvider` (local/remote/custom), `IImageProvider`, `IMetadataSaver`, `IExternalId`, `IExternalUrlProvider`, ordered per-library by `TypeOptions.MetadataFetcherOrder`/`ImageFetcherOrder`/`LocalMetadataReaderOrder`; refreshes run through a priority queue to a type-specific `IMetadataService`. NFO (Kodi/XBMC) reading/saving is a built-in local provider (`MediaBrowser.XbmcMetadata`); TMDB/TVDB/OMDb/AniDB/AniList are plugins.

### Cited Findings

## Q4. Media probing (ffprobe, MediaSourceInfo/MediaStream, attachments/fonts)

## Q5. Playback decisions: DeviceProfile, StreamBuilder, PlaybackInfo, subtitle burn-in vs sidecar/embedded (ASS/SSA handling)

### Takeaway
`POST /Items/{id}/PlaybackInfo` with a `DeviceProfile` runs the server-side `StreamBuilder` (MediaBrowser.Model/Dlna) which, per `MediaSourceInfo`, checks `DirectPlayProfiles` + `CodecProfiles` + `ContainerProfiles`, accumulates `TranscodeReason` flags, and picks `DirectPlay` (zero failures), `DirectStream` (only container/audio-tolerable failures → remux), or `Transcode` (ranked `TranscodingProfiles`). Subtitles are resolved by `GetSubtitleProfile`: it tries `Embed` profiles (only when not HLS-transcoding and the container supports embedding, i.e. mkv), then `External`/`Hls` profiles (`Hls` only for text streams while transcoding), and falls back to `Encode` = burn-in. ASS/SSA are text (`IsTextFormat`), can be delivered externally as-is, but `SupportsSubtitleConversionTo` forbids converting ASS/SSA to or from anything, so a client without an `External`/`Embed` profile for `ass`/`ssa` forces burn-in.

### Inferences
- "Burn in vs deliver" is decided entirely by the client-supplied `SubtitleProfiles`: a client that lists `{Format:"ass", Method:"External"}` gets the ASS file as-is (plus fonts via Attachments); a client lacking that but listing `{Format:"ass", Method:"Embed"}` gets it embedded only when direct-playing/direct-streaming an mkv; under HLS transcoding, ASS cannot be embedded (ts/fmp4 don't carry ASS) and cannot be converted to WebVTT by `SupportsSubtitleConversionTo` (ass/ssa are blocked both as source and target), so unless the client takes `External` ASS, the server falls through to `Encode` (libass burn-in). This is the core reason ASS-heavy anime libraries transcode so often on TV/mobile clients.
- The "hardware ASS rendering" improvement in 10.11 corresponds to the `alphasrc`→`hwupload`→`overlay_*` path where libass output is composited on-GPU instead of forcing a `hwdownload`.
- The `sub2video` flag in the libass filter enables ffmpeg's subtitle-to-video path (needed for bitmap subs in text filter context); its presence in `GetTextSubtitlesFilter` suggests the same code path handles some edge cases for text subs.

## Q6. Transcoding pipeline: TranscodingJob, HLS via ffmpeg, seeking/segment regeneration, hardware acceleration, subtitle extraction/conversion

### Takeaway
HLS transcodes are driven on demand by `DynamicHlsController`: `master.m3u8` (DynamicHlsHelper) advertises variants/subtitle groups/trickplay, `main.m3u8` (`DynamicHlsPlaylistGenerator`, optionally keyframe-aligned) lists every segment up front with `runtimeTicks`/`actualSegmentLengthTicks` query params, and each `hls1/{playlist}/{segmentId}.{ts|mp4}` request either serves an existing file or (re)starts a single ffmpeg using the HLS muxer (`-f hls -hls_time N -hls_list_size 0 -start_number {segmentId}`), killing the previous job when the requested segment is before the current one or more than `24/SegmentLength` segments ahead. `EncodingHelper` assembles decoder/encoder/filter chains per vendor (VAAPI, QSV, NVENC/CUDA, AMF/D3D11+OpenCL/Vulkan, VideoToolbox, RKMPP, V4L2M2M). `SubtitleEncoder` extracts embedded tracks with ffmpeg (`-c:s copy` for ass/ssa/srt/pgs/vobsub, else `srt`) into a cache with `.meta` sidecars and converts text formats with SubtitleEdit-derived writers.

### Cited Findings

### Inferences
- The design is "playlist first, segments lazily": the full VOD playlist is synthesized from runtime (or keyframes) before any encoding, so the client can seek anywhere; a seek maps to a segment index and the server restarts ffmpeg at `segmentId × SegmentLength` using `-ss` + `-start_number`. `-copyts` plus `avoid_negative_ts disabled` keeps PTS aligned across restarts so the player's timeline stays monotonic. The "non-keyframe break" log line shows the known weakness: segment boundaries assume keyframe alignment; with `BreakOnNonKeyFrames` now obsolete/always false, accurate seeking depends on `-force_key_frames` style GOP control in the encoder args (not visible in the fetched excerpt).
- The 60-second HLS ping timeout plus per-request counting is what lets the server GC orphaned ffmpeg processes without explicit "stop" calls; a clone needs the same.

## Q8. Authentication, users, permissions, parental controls, Quick Connect, LDAP/SSO

### Takeaway
Auth is a custom ASP.NET scheme ("CustomAuthentication") that parses `Authorization: MediaBrowser Client="…", Device="…", DeviceId="…", Version="…", Token="…"` (legacy `X-Emby-Authorization`, `Emby` scheme, `X-Emby-Token`, `X-MediaBrowser-Token`, `api_key` are behind `EnableLegacyAuthorization`, slated for removal in 10.12); tokens resolve to a Device row (user session) or an ApiKey row (`IsApiKey`, no user). Quick Connect issues a 6-digit code + 64-hex secret with a 10-minute expiry. Users carry policy columns and `Permission`/`Preference`/`AccessSchedule` collections; parental control uses `MaxParentalRatingScore`/`SubScore` (10.11 `ratingScore` model). LDAP/SSO are `IAuthenticationProvider` plugins.

## Q9. Plugin system, scheduled tasks, DI

### Takeaway
Plugins are .NET assemblies loaded from `plugins/<Name>/`, built against the `Jellyfin.Controller`/`Jellyfin.Model` NuGet packages (version must match server), subclassing `BasePlugin<TConfig>`; they extend the server by implementing discovered interfaces (`IScheduledTask`, `IRemoteMetadataProvider`, `IImageProvider`, `IMetadataSaver`, `IAuthenticationProvider`, `ISubtitleProvider`, `ControllerBase` endpoints) and register DI services via `IPluginServiceRegistrator`; since 10.11 any DB access must go through EF Core and a "HIGHLY experimental" plugin DB API exists.

### Cited Findings
- Template requirements: `BasePlugin<PluginConfiguration>` + `BasePluginConfiguration`; ctor `(IApplicationPaths, IXmlSerializer)`; `Name`, `Id` (GUID); `IPluginConfigurationPage`; `IPluginServiceRegistrator` found at startup; `IScheduledTask`; `IHostedService` (not on the main plugin class); `ControllerBase` REST endpoints; `IMetadataSaver`; `<ExcludeAssets>runtime</ExcludeAssets>`; GPLv3 packages; load path `plugins/<PluginName>/` — [jellyfin-plugin-template](https://github.com/jellyfin/jellyfin-plugin-template)
- Plugin folder locations and XML config persistence in `configurations/`; plugin catalog + manifest repos; categories — [Plugins docs](https://jellyfin.org/docs/general/server/plugins/)
- 10.11: "All database access must go through EF Core… raw SQL will no longer be accepted"; plugin custom DB access API "HIGHLY experimental", stability targeted for 10.12 — [10.11.0 release post](https://jellyfin.org/posts/jellyfin-release-10.11.0)
- 10.9: in-process restart "makes plugin installs more robust"; 10.10: media segments storage with a plugin needed to create segments (e.g. from chapter names) — [10.9.0](https://jellyfin.org/posts/jellyfin-release-10.9.0); [10.10.0](https://jellyfin.org/posts/jellyfin-release-10.10.0)
- `Emby.Server.Implementations` "Includes ScheduledTasks"; `ProviderManager.AddParts` and `LibraryManager.AddParts` receive discovered implementations (`IItemResolver`, `IMultiItemResolver`, `IResolverIgnoreRule`, `ILibraryPostScanTask`, providers) — [Source tree docs](https://jellyfin.org/docs/general/contributing/source-tree/); [LibraryManager.cs](https://github.com/jellyfin/jellyfin/blob/master/Emby.Server.Implementations/Library/LibraryManager.cs); [ProviderManager.cs](https://github.com/jellyfin/jellyfin/blob/master/MediaBrowser.Providers/Manager/ProviderManager.cs)

### Inferences
- The "AddParts" pattern (host scans all loaded assemblies for interface implementations and injects arrays into managers) is the Emby-era extension mechanism and coexists with modern `IServiceCollection` DI; a plugin can also inject core services (`ILibraryManager`, `IUserManager`) directly.

### Gaps
- `meta.json`/`build.yaml` manifest fields (`targetAbi`, `guid`, `version`, `changelog`) and `PluginManager` load/ABI checks were not fetched.

## Q10. SyncPlay, trickplay, image processing, networking, API surface, Live TV

### Takeaway
SyncPlay is a server-side group state machine (Idle/Waiting/Paused/Playing) that broadcasts timestamped commands (`When` = UTC) over the websocket and holds the group in `Waiting` until all members report ready, with per-member ping (default 500 ms, max 10 s) and a 30 s wait timeout. Trickplay generates JPEG tile sheets (default 10×10) per width via ffmpeg + `IImageEncoder.CreateTrickplayTile` (SkiaSharp), stored in metadata (or beside media) and exposed as images and an `#EXT-X-IMAGES-ONLY` HLS playlist. Kestrel hosts everything under `BaseUrl`; DLNA is a plugin since 10.9; OpenAPI/Swagger is served by `UseJellyfinApiSwagger`.

### Cited Findings
- `Group.cs`: states `IdleGroupState`→`WaitingGroupState`→`PlayingGroupState`/`PausedGroupState`; `HandleRequest` → `request.Apply(this, _state, session, ct)`; `NewSyncPlayCommand(SendCommandType)` builds `SendCommand` with `PositionTicks` and `When = DateTime.UtcNow`; `DefaultPing = 500 ms`, `MaxPing = 10000 ms`, `TimeSyncOffset = 2000 ms`, `MaxPlaybackOffset = 500 ms`, `DefaultGroupWaitTimeout = 30000 ms`; `GetHighestPing`; `HandleGroupWaitTimeout` resumes without stragglers or pauses the group; `PlayQueueManager` with `SetPlayQueue`, `AddToPlayQueue` (QueueNext), repeat/shuffle; updates `SyncPlayGroupJoinedUpdate`, `SyncPlayUserJoinedUpdate`, `SyncPlayUserLeftUpdate`, `SyncPlayGroupLeftUpdate`, `SyncPlayStateUpdate`; broadcast types `CurrentSession`, `AllGroup`, `AllExceptCurrentSession`, `AllReady`; "not thread-safe… external locking is required" — [Group.cs](https://github.com/jellyfin/jellyfin/blob/master/Emby.Server.Implementations/SyncPlay/Group.cs)
- `TrickplayManager.RefreshTrickplayDataAsync`: skips placeholders/shortcuts/short videos; `Interval` ≥1000 ms; per-`WidthResolutions` `RefreshTrickplayDataInternal` under a global `AsyncNonKeyedLocker(1)`; width forced even and capped at source width; `SaveTrickplayWithMedia` writes a `.jellyfin-trickplay` marker; calls `IMediaEncoder.ExtractVideoImagesOnIntervalAccelerated` (hwaccel/hw-encode flags, threads, qscale, priority, keyframe-only); `CreateTiles` groups frames into `TileWidth×TileHeight` chunks → `IImageEncoder.CreateTrickplayTile(JpegQuality, width)`; `Bandwidth` = peak tile bits/count/interval; output `{base}/{width} - {tileW}x{tileH}/{index}.jpg`; `TrickplayInfo` {ItemId, Width, Height, Interval, TileWidth, TileHeight, ThumbnailCount, Bandwidth}; `GetHlsPlaylist` emits `#EXT-X-IMAGES-ONLY`, `#EXT-X-PLAYLIST-TYPE:VOD`, per-tile `#EXTINF` + `#EXT-X-TILES:RESOLUTION=…,LAYOUT=…,DURATION=…`, URIs `{i}.jpg?MediaSourceId=…&ApiKey=…` — [TrickplayManager.cs](https://github.com/jellyfin/jellyfin/blob/master/Jellyfin.Server.Implementations/Trickplay/TrickplayManager.cs)
- Trickplay extraction: `MaxFramerate = 1/interval`, filter chain from `EncodingHelper.GetVideoProcessingFilterParam`, `setpts=N/<fps>/TB,` before `fps=` unless keyframe-only, output `%08d.jpg`, quality via `-qscale:v`/`-global_quality:v`/`-qp_init:v`, keyframe-only attempt first then standard retry, progress by counting JPEGs — [MediaEncoder.cs](https://github.com/jellyfin/jellyfin/blob/master/MediaBrowser.MediaEncoding/Encoder/MediaEncoder.cs)
- `TrickplayOptions` fields: TileWidth, TileHeight, Interval, WidthResolutions, JpegQuality, EnableHwAcceleration — [TS SDK TrickplayOptions](https://typescript-sdk.jellyfin.org/interfaces/generated-client.TrickplayOptions.html); forum: default tile grid 10×10, files under metadata `trickplay/{resolution}/N.jpg`, ~15 JPGs/hour at 5×5 ≈ 4.5–6 MB, Roku needed 5×5 — [forum](https://forum.jellyfin.org/printthread.php?tid=5972); [forum](https://forum.jellyfin.org/printthread.php?tid=10145); [forum](https://forum.jellyfin.org/t-trickplay-and-chapter-images-storage-location)
- 10.9 introduced native trickplay (client support required); 10.10 added keyframe-only extraction (~100x faster) and a long migration on upgrade — [10.9.0](https://jellyfin.org/posts/jellyfin-release-10.9.0); [10.10.0](https://jellyfin.org/posts/jellyfin-release-10.10.0)
- `Jellyfin.Drawing.Skia` = image manipulation (resize, collages); `Emby.Drawing` = image processor managing encoder + cache paths; `Jellyfin.Networking` manages interfaces/settings; `RSSDP` customized SSDP — [Source tree docs](https://jellyfin.org/docs/general/contributing/source-tree/)
- DLNA moved to an optional plugin in 10.9, disabled unless installed, "reduces DLNA-related security exposure"; SSDP/DLNA respect IP binding — [10.9.0](https://jellyfin.org/posts/jellyfin-release-10.9.0)
- 10.11: internal TLS deprecated (use reverse proxy; manual Kestrel TLS stays but not in UI); startup web UI with log viewer accessible only from configured local networks; backup/restore `BackupApi` (restore only on the same system) — [10.11.0](https://jellyfin.org/posts/jellyfin-release-10.11.0)
- `UseJellyfinApiSwagger`, `UseIPBasedAccessValidation`, `UseBaseUrlRedirection`, `UseForwardedHeaders`, `MapHealthChecks("/health")`, optional Prometheus `UseHttpMetrics`/`MapMetrics`; `AutoDiscoveryHost` hosted service (UDP discovery) — [Startup.cs](https://github.com/jellyfin/jellyfin/blob/master/Jellyfin.Server/Startup.cs)
- Live TV: `AddLiveTvServices`, `RecordingsHost`, `RecordingNotifier`; NextPVR and TVHeadend are official plugins; 10.11 M3U tuners can use native framerate; `RewritePublishedLiveStreamPath` rewrites `/LiveTv/LiveStreamFiles/` paths — [Startup.cs](https://github.com/jellyfin/jellyfin/blob/master/Jellyfin.Server/Startup.cs); [Plugins docs](https://jellyfin.org/docs/general/server/plugins/); [MediaInfoHelper.cs](https://github.com/jellyfin/jellyfin/blob/master/Jellyfin.Api/Helpers/MediaInfoHelper.cs)
- SyncPlay reliability: user reports of failures behind reverse proxies and claims the original developer left; guides say it works on web-wrapper clients — [forum](https://forum.jellyfin.org/t-jellyfin-syncplay-doesn-t-work-on-synology-nas-server); [Android Authority](https://www.androidauthority.com/jellyfin-syncplay-explained-3530437/)

### Inferences
- SyncPlay's correctness depends on clients estimating clock offset against the server (the `TimeSyncOffset` tolerance and `GetUtcTime`-style exchange) and on every client honoring "schedule at UTC `When`"; native clients that don't implement the state machine break the group, which matches the user reports.

### Gaps
- `PlaybackController`/`/GetUtcTime` client-side time sync code, the `IGroupState` implementations, and the `TrickplayController` route definitions were not fetched.
- Media segments API shape (`MediaSegments/{itemId}`, segment types Intro/Outro/Recap/Preview/Commercial) was not verified from source.

## Q11. The 10.11 database/EF Core migration: scope and why it took years

### Takeaway
The migration replaced scattered raw SQLite calls (no ORM) with EF Core across the whole library schema, merged `library.db` into `jellyfin.db` with real foreign keys, and deduplicated/repaired logically corrupt data on upgrade; it began ~2019–2020 with Users/Auth, stalled for years on the library DB until one contributor (JPVenson) finished it, then needed ~6 months of dev + 6 months of RC and still produced migration failures and client-side-enumeration performance regressions that took five+ point releases to settle.

### Cited Findings
- "The Library Database conversion to EF Core is complete!"; conversion "started almost 5 years ago" with Users and Authentication; library DB stalled "for several years" until JPVenson completed it; pre-10.11 had "effectively zero centralization of the database management functionality into an ORM"; migration moves `library.db` → `jellyfin.db`, adds foreign keys, deduplicates and fixes logical corruption (orphan items, duplicate People); duration depends on data condition ("300,000 entries but no issues" minutes vs "30 series but severe inconsistencies" hours); upgrade must come from 10.10.7 (10.9.11 "may" work, others "WILL fail"); original renamed `library.db.old`; refuses to start with <2 GB free; in-memory cache "up to the full size of your Library database"; PostgreSQL "not officially yet"; new SQLite locking modes — [10.11.0 release post](https://jellyfin.org/posts/jellyfin-release-10.11.0)
- "six months of development and six months of release candidate testing"; "four additional point releases with over 100 changes"; remaining migration issues are "isolated one-off cases"; team investigating "client-side handling of large datasets"; versioning feedback → considering 12.0 — [State of the Fin 2026-01-06](https://jellyfin.org/posts/state-of-the-fin-2026-01-06)
- Secondary (vendor blog, partly unsourced): work began 2019; migration failures tracked in GitHub #15027, #15060, #15686 (hung startups, partial migrations, lost watch history for users without backups); regressions: collections 10–15 s, large home pages 30–50 s, Home Videos >16k items not loading, 500+ item playlists 30+ s; cause attributed to EF Core "client-side enumeration" (loading full datasets into memory and filtering in code); point releases 10.11.1 (migration/startup), .2 (performance, Home Videos), .3 (watched status), .4 (music metadata), .5 (Xbox/stability), .7 (4 security + 25 fixes); by 10.11.5 (March 2026) most migration bugs fixed — [JellyWatch analysis](https://jellywatch.app/blog/jellyfin-10-11-ef-core-migration-chaos-lessons-learned-2026) (note: article's "hundreds of users" figures are unsourced and it is a commercial vendor)
- 10.11.11 announced 6 June 2026 as a bugfix release — [forum release thread](https://forum.jellyfin.org/t-new-jellyfin-server-web-release-10-11-11); described as a hotfix for user-manager concurrency — [JellyWatch](https://jellywatch.app/blog/jellyfin-10-11-11-update-stable-release)
- Plugin consequence: raw SQL no longer accepted; plugin DB access API experimental until 10.12 — [10.11.0 release post](https://jellyfin.org/posts/jellyfin-release-10.11.0)

### Inferences
- Lessons for a from-scratch build: (1) pick the ORM/schema on day one — retrofitting one onto a type-string + JSON-blob item table with ad-hoc SQL took half a decade of volunteer time; (2) "logical corruption" accumulates when integrity isn't enforced by the DB, and the migration had to double as a repair tool; (3) in-DB vs in-memory query translation is a real risk with EF Core + a semi-structured item model (filters on JSON-blob fields can only run client-side); (4) a small RC tester pool cannot cover the long tail of library shapes (deep nesting, 16k-item Home Videos, 500-item playlists).

### Gaps
- No official Jellyfin post-mortem beyond the State of the Fin paragraph; GitHub issue numbers come from a secondary source and were not verified.

## Q12. What is inherited from Emby and considered technical debt

### Takeaway
Officially documented inheritance is limited to "descended from Emby 3.5.2"; the Emby-era structure is still visible in project names (`Emby.*`, `MediaBrowser.*`), the DLNA-shaped `DeviceProfile`/`StreamBuilder` living in a `Dlna` namespace, ServiceStack-era route leftovers, `X-Emby-*`/`Emby` auth scheme compatibility (being removed in 10.12), the un-ORM'd SQLite layer (replaced in 10.11), and the "AddParts" plugin pattern. The team's own words for the old DB layer are "spaghetti".

### Cited Findings
- "descended from Emby's 3.5.2 release and ported to the .NET platform" — [GitHub README](https://github.com/jellyfin/jellyfin); Emby's public repo "stops dead in September 2018 at tag 3.5.3" and the projects have diverged for eight years (secondary) — [techfuelhq](https://techfuelhq.com/homelab/jellyfin-vs-emby-2026/)
- Project names `Emby.Naming`, `Emby.Photos`, `Emby.Server.Implementations`, `Emby.Drawing`, `MediaBrowser.*` ("MediaBrowser" was Emby's earlier name) remain in the tree — [Source tree docs](https://jellyfin.org/docs/general/contributing/source-tree/)
- `DynamicHlsController` segment route's `playlistId` parameter is "unused and marked as imported from ServiceStack" (Emby used ServiceStack before Jellyfin moved to ASP.NET Core controllers) — [DynamicHlsController.cs](https://github.com/jellyfin/jellyfin/blob/master/Jellyfin.Api/Controllers/DynamicHlsController.cs)
- `StreamBuilder`, `DeviceProfile`, `SubtitleProfile`, `TranscodingProfile` live in `MediaBrowser.Model.Dlna` with DLNA-specific fields (`DidlMode`, `DlnaProfileType`, `EnableMpegtsM2TsMode`, obsolete `BreakOnNonKeyFrames`) even though DLNA itself moved to a plugin — [SubtitleProfile.cs](https://github.com/jellyfin/jellyfin/blob/master/MediaBrowser.Model/Dlna/SubtitleProfile.cs); [TranscodingProfile.cs](https://github.com/jellyfin/jellyfin/blob/master/MediaBrowser.Model/Dlna/TranscodingProfile.cs); [10.9.0](https://jellyfin.org/posts/jellyfin-release-10.9.0)
- Legacy `Emby` auth scheme, `X-Emby-Authorization`, `X-Emby-Token`, `X-MediaBrowser-Token`, `api_key` are gated by `EnableLegacyAuthorization` and slated for removal in 10.12 — [AuthorizationContext.cs](https://github.com/jellyfin/jellyfin/blob/master/Jellyfin.Server.Implementations/Security/AuthorizationContext.cs); [10.11.0](https://jellyfin.org/posts/jellyfin-release-10.11.0)
- Legacy playback routes (`Users/{userId}/PlayingItems/...`) are `[Obsolete]` and hidden from API docs — [PlaystateController.cs](https://github.com/jellyfin/jellyfin/blob/master/Jellyfin.Api/Controllers/PlaystateController.cs)
- The 10.11 post frames the EF Core work as removing legacy "spaghetti" code — [10.11.0](https://jellyfin.org/posts/jellyfin-release-10.11.0)
- `User.InternalId` is documented as a "temporary ID corresponding to the user's index in the library database" — [User.cs](https://github.com/jellyfin/jellyfin/blob/master/src/Jellyfin.Database/Jellyfin.Database.Implementations/Entities/User.cs)
- Web client `src/legacy` holds polyfills and `src/libraries` holds dependencies "intended to be removed eventually" — [Source tree docs](https://jellyfin.org/docs/general/contributing/source-tree/)
- `TranscodeReason` mapping has conditions returning 0 "with a TODO" (`IsAvc`, `NumStreams`, `VideoTimestamp`) — [StreamBuilder.cs](https://github.com/jellyfin/jellyfin/blob/master/MediaBrowser.Model/Dlna/StreamBuilder.cs)
- The `"MediaBrowser"` auth scheme and `Emby`-compatible headers are the "emby compatibility" surface; Jellyfin's OpenAPI is generated from the ASP.NET controllers (`AddJellyfinApiSwagger`/`UseJellyfinApiSwagger`), and the SDKs are generated from the resulting `openapi.json` — [Startup.cs](https://github.com/jellyfin/jellyfin/blob/master/Jellyfin.Server/Startup.cs); [TS SDK README](https://github.com/jellyfin/jellyfin-sdk-typescript)

### Inferences
- The highest-leverage debt items for a clone to avoid: DLNA-flavored playback profile model as the universal capability language; type-name + blob item persistence; two parallel implementation projects during migrations; per-request query-string "API key in URL" patterns for media URLs (needed because `<video src>` can't set headers, but it leaks tokens into logs).

### Gaps
- No official inventory of Emby-derived files; this section's "debt" judgments are inferred from naming, `[Obsolete]` markers, TODOs, and release-post language.

## Q13. Client SDK ecosystem and what a client must implement to play content

### Takeaway
Official SDKs (`@jellyfin/sdk` TypeScript, `jellyfin-sdk-kotlin`, plus the older `jellyfin-apiclient-javascript` used by jellyfin-web and a Swift SDK used by Swiftfin) are generated from the server's `openapi.json`. A minimal player: authenticate (or Quick Connect) → build a `DeviceProfile` → `POST Items/{id}/PlaybackInfo` → pick a `MediaSource` → direct play (`Videos/{id}/stream.{container}?Static=true&MediaSourceId&DeviceId&ApiKey[&Tag]`) or load `TranscodingUrl` (`master.m3u8`) → attach external subs via `MediaStream.DeliveryUrl` and fonts via `MediaAttachments[].DeliveryUrl` → `POST Sessions/Playing`, progress every ~10 s, `Sessions/Playing/Stopped`.

### Cited Findings
- TS SDK: npm `@jellyfin/sdk`, MPL-2.0, "generated Axios client" from `openapi.json` with `openapitools.json`/custom templates; `new Jellyfin({clientInfo, deviceInfo:{name,id,languages}})`, `createApi(address)`, helpers under `/lib/utils/api/` (`getSystemApi`, `getUserApi`, `getAuthenticationApi`, `getLibraryApi`, `getSessionApi`…); `getRecommendedServerCandidates` + `findBestServer`; version map SDK 1.0.0 → Jellyfin 12.x, 0.12/0.13 → 10.11.x, 0.11 → 10.10.x, 0.9/0.10 → 10.9.x, 0.7–0.8.2 → 10.8.x; React Native needs `URL` polyfills — [TS SDK README](https://github.com/jellyfin/jellyfin-sdk-typescript)
- Kotlin SDK: modules `jellyfin-core`, `jellyfin-api`, `jellyfin-api-okhttp`, `jellyfin-model`, `openapi-generator`; LGPL-3.0; JVM + Android ≥4.4 (desugaring <8); `createJellyfin { clientInfo }`, `createApi(baseUrl, accessToken, clientInfo, deviceInfo, httpClientOptions)`, `authenticateUserByName` → `api.update(accessToken=)`; `api.webSocket.subscribeAll()`; discovery `jellyfin.discovery.discoverLocalServers()`, `getAddressCandidates()`, `getRecommendedServers()` with `RecommendedServerInfoScore.GOOD` — [Kotlin SDK repo](https://github.com/jellyfin/jellyfin-sdk-kotlin); [Kotlin SDK guide](https://kotlin-sdk.jellyfin.org/guide/getting-started.html)
